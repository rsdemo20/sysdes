# sysdes — балльная оценка решения и нормализация

Статус: Baseline 1.0. Подтверждены контекстные веса, частичный зачёт и referenceScore=1500 как ориентир для 100%. Исходный балл может быть выше, максимальный процент и уровень оценки при этом не повышаются. Q-13 закрыт: общая оценка дополняет три диагностики, рубрику утверждает владелец до публикации. Спецификация дополняет диагностику отдельных схем из [04-ai-evaluation.md](04-ai-evaluation.md).

## Подтверждённые принципы

- Шаблон содержит HLD, ER и Sequence с общей задачей и критериями. Ответ может включать схемы, свободный текст у блоков, описания диаграмм и общие пояснения.
- В некоторых сценариях основная доля оценки, ориентировочно 80–90%, относится к HLD. Этот акцент не навязывается всем доменам и Custom.
- Цена относится к выполняемому условию рубрики конкретного домена/сценария, а не к типу графического блока или названию технологии. Один Redis в разных задачах может иметь разный вес; отдельные детали могут стоить доли процента итоговой шкалы.
- Наброски ER/Sequence, правильные выборы и содержательный текст могут давать частичный или полный зачёт пунктов. Максимум и уровни зависят от условий данного пункта.
- Заполнять весь условный чек-лист не обязательно. Ценные независимые детали могут компенсировать неточности HLD; количество заполненных объектов/полей не является оценкой.
- Начисление по одному пункту не превышает его максимум. Текст и диаграмма являются доказательствами выполнения, а не независимыми поводами дважды начислить те же баллы.

## Команды оценки и подготовка рубрики

Подтверждены четыре независимые команды: «Оценить решение», «Оценить HLD», «Оценить ER», «Оценить Sequence». Общая оценка использует единый снимок всего решения и показывает rawScore, referenceScore, процент и отчёт с разбором пунктов. Отдельные диагностики дают подробную обратную связь по выбранному типу схемы; их результаты не суммируются для получения общего балла.

Владелец утверждает рубрику каждого шаблона до публикации: пункты, контекстные веса, уровни частичного зачёта, допустимые альтернативы и referenceScore. AI допустим как инструмент подготовки рубрики; при оценке ответа он сопоставляет доказательства готовым пунктам и не изобретает новые веса. Создание холста не требует отдельного AI-вызова для генерации рубрики. Для Custom заранее подготовлена общая рубрика.

Рубрики хранятся в БД и версионируются; GUI их редактирования не входит в MVP. Опубликованная версия неизменяема и доступна для воспроизведения старой оценки. В snapshot запуска сохраняется применённая рубрика. Предлагается связывать созданный холст с версией рубрики выбранного шаблона, а Custom — с действующей общей версией на момент создания; обновление каталога не меняет эту привязку молча.

## Балльная шкала и ориентир 1500

Вместо фиксированной стоимости пунктов в процентах используются **баллы рубрики** и **referenceScore=1500** — подтверждённый пользователем ориентир для 100%. Значения 700 и 1200 остаются предложенными ориентирами среднего/хорошего ответа и требуют калибровки; они не являются измеренной статистикой пользователей.

| Ориентир пользователя | Баллы | Процент при referenceScore = 1500 |
|---|---:|---:|
| Условный средний ответ | 700 | 46,67% |
| Хороший ответ | 1200 | 80,00% |
| Полный ответ / ориентир для 100% | 1500 | 100,00% |
| Результат выше ориентира | 1650 | 100,00% |
| Ещё больше набранных баллов | 2000 | 100,00% |

Фактический средний результат требует измерений на примерах. Для калибровки используется предусмотренный pilot AI: ответы разной полноты и экспертная оценка. Новая продуктовая аналитика не требуется. Одинаковая шкала сама по себе не доказывает сопоставимость сложности разных доменов.

Вопрос 6 закрыт прямым ответом пользователя: 1500 — ориентир для 100%, а не потолок набранных баллов. Исходный результат сохраняется и показывается полностью; 1500, 1650 и 2000 баллов дают один максимальный уровень оценки и 100%. Сумма весов всех потенциально полезных пунктов не обязана равняться referenceScore: избыток доступных баллов позволяет получить полный результат за разные наборы ценных решений.

## Частичный зачёт и цена в контексте

Ранний пример пользователя «8% за пункт кэширования корзины, 3% за текст без блока» иллюстрирует частичный зачёт. Эти числа не являются обязательной ценой Redis или универсальным коэффициентом 3/8 для текста.

Следующие цифры — только примеры рубрик, не предписания для реальных доменов. При referenceScore = 1500:

| Условная рубрика | Максимум пункта | Частичный ответ текстом | Вклад текста / максимума в общий процент |
|---|---:|---:|---|
| Сценарий A: соответствующий пункт кэширования | 120 баллов | 45 баллов | 3,00% / 8,00% |
| Сценарий B: другая роль кэширования | 9 баллов | 3 балла | 0,20% / 0,60% |

Уровни пункта выбираются по достаточности ответа: отсутствует нужное решение → 0; релевантная, но неполная рекомендация → частичный зачёт; полное корректное решение → максимум. Простой прямоугольник с названием Redis не доказывает выполнение условия. Неоднозначность, противоречие текста и схемы или неподходящий выбор отражаются в объяснении оценки.

В сценарии A частичный ответ даёт 45 из 120, недостаёт 75. Полная схема вместе с текстом даёт максимум 120, не 165. Один пункт принадлежит одной части рубрики: восстановленные текстом баллы HLD-пункта уже входят в hldScore и повторно не начисляются в additionalScore. Независимые свойства одного объекта могут подтверждать разные пункты.

Результат содержит ID пункта, его максимум, выбранный уровень, начисленные баллы, объяснение и evidenceRefs на существующие объекты/текст. Пользователь не обязан вручную отмечать чек-лист; AI сопоставляет ему свободный ответ. Эквивалентные обоснованные решения допустимы, совпадение рисунка с единственным шаблоном не требуется.

## Расчёт и детали рубрики

Каждая версия рубрики фиксирует домен/сценарий, referenceScore, состав частей и пунктов, максимумы, уровни зачёта и допустимые альтернативы. Рекомендуются целые исходные баллы: 1 из 1500 уже соответствует примерно 0,0667%. Для таких деталей дробные баллы не нужны.

```text
rawScore = hldScore + additionalScore
referenceScore = 1500
normalizedPercent = 100 * rawScore / referenceScore
progressPercent = min(100, normalizedPercent)
```

hldScore и additionalScore вычисляет backend из проверенных результатов по непересекающимся пунктам; AI не задаёт произвольные итоговые суммы. Каждый пункт начисляется один раз в пределах своего максимума; варианты взаимоисключающего решения не суммируются как независимые достижения. referenceScore должен быть положительным, баллы конечными и неотрицательными, уровни — разрешёнными рубрикой.

Для профиля с ориентиром 1500 и акцентом HLD 80% можно предложить максимум HLD 1200 и более 300 доступных баллов в дополнительной части. Например, HLD 1050 + независимые дополнительные пункты 450 = 1500: ценность деталей компенсирует недочёт 150 баллов. Конкретные веса остаются содержанием рубрики сценария; готового глобального прайса технологий нет.

Процент рассчитывается по исходной сумме, без предварительного округления вкладов пунктов. Для итогового UI предлагаются два знака после запятой; полный результат определяется сравнением исходных баллов с referenceScore, не округлённой надписью 100%. Исходный rawScore сохраняется и показывается без обрезания до 1500. В UI процентом итоговой оценки является progressPercent; normalizedPercent может превышать 100 только как промежуточное значение расчёта. Набор сверх referenceScore не вводит уровень выше максимального.

Величина 700 не является знаменателем нормализации и не означает 50-й перцентиль без измерений. Процент показывает отношение к ориентиру рубрики, а не долю пользователей, которых обошёл ответ, и не долю заполненных полей.

Изменение весов, уровней или referenceScore выпускает новую версию рубрики. Результат хранит применённую версию и ориентир; прежние оценки не пересчитываются молча. Для сравнения между версиями/доменами показывается контекст рубрики. Возможность переоценить один и тот же снимок остаётся отдельным явным запуском.

Замечания сохраняют важность независимо от баллов. Высокий результат характеризует представленное проектное решение и не доказывает фактическую приёмку работающего приложения.

## Полный результат как условие публикации

Действие «Добавить в каталог» по D-45 разрешено только при выполненном `maximumReached`, то есть при rawScore не ниже referenceScore до округления. Надпись «100%» в интерфейсе условием не является: `progressPercent` ограничен сотней и достигает её же при округлении близких значений, поэтому проверку выполняет сервер по исходным баллам, а не по проценту и не по значению, присланному клиентом. Условию соответствует только общая оценка решения: диагностики hld/er/sequence используют шкалу 1–5, у них нет rawScore и они публикацию не открывают. Статус insufficient_data оставляет rawScore null и также не открывает её.

Отчёт должен быть неустаревшим: документ холста обязан совпадать со снимком, по которому получен результат. Любая правка после оценки делает отчёт устаревшим по FR-22, и публикация отклоняется до повторного запуска. Смена рубрики на новую версию не пересчитывает прежний результат и не отзывает уже опубликованную запись каталога: публикация неизменяема и хранит применённую версию рубрики вместе с содержимым. Достигнутые 100% характеризуют решение по конкретной рубрике и ориентиру, а не абсолютное качество; опубликованная запись становится оцениваемым заданием только после того, как владелец утвердит для неё рубрику по D-17.

## Границы текущего машинного контракта

Q-13 закрыт ответами 4A/5A/6A, формат результата — 24A. [Рубрика](contracts/rubric.schema.json), [ответ AI](contracts/provider-result.schema.json) и [серверный результат v2](contracts/evaluation-result-v2.schema.json) входят в baseline. В первой версии исходные баллы целые: 1/1500 уже даёт доли процента; размер каждого пункта задаётся сценарием.

`evaluation-result.schema.json` v1 оставлен как исторический диагностический пример. Рабочий контракт v2 различает solution с серверными rawScore/referenceScore/progressPercent и hld/er/sequence с overallScore 1–5. Все пункты рубрики присутствуют в AI-ответе один раз: levelId разрешён рубрикой либо null при неопределённости. evaluated не допускает null-уровней; insufficient_data сохраняет общий балл/процент null, не превращая неизвестное в ноль.

Общая оценка работает по одному снимку с текстами участвующих областей; результаты разных revisions не складываются. Активный текст включается через flush по 11/12, релевантные тексты входят в hash входа. Проверки — AC-37…40 в [06-acceptance.md](06-acceptance.md); расчёт не требует кликстрима.
