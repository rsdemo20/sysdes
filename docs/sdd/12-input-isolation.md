# sysdes — изоляция текстового ввода (Input Isolation)

Статус: Baseline 1.0. Уточнение MVP по запросу пользователя. Связанные FR: 05, 09, 10, 24; приёмка — AC-33…36 в [06-acceptance.md](06-acceptance.md).

## Проверка решения

Локальный черновик и commit по `onBlur` / Enter подходят для sysdes. Уточнение причины: обновление Zustand само по себе не означает перерисовку всего графа; стоимость зависит от подписок, изменившихся ссылок и структуры компонентов. Поэтому нужны и изоляция поля, и узкие подписки, и стабильные props. React Flow рекомендует мемоизацию компонентов/обработчиков и избегать подписки на весь nodes/edges там, где нужны отдельные данные. [React Flow: Performance](https://reactflow.dev/learn/advanced-use/performance).

| Вариант | Решение для MVP |
|---|---|
| Локальный controlled input: `useState` в небольшом компоненте поля внутри CustomNode | Рекомендуется: мгновенный локальный отклик, явные валидация, commit и сброс |
| Uncontrolled input: значение в DOM, чтение через ref | Допустимая альтернатива при тех же гарантиях; сложнее явно синхронизировать смену документа и Undo |
| Синхронизация с графом из onChange, сразу либо через debounce | Не выбрана как основной путь: debounce сокращает частоту записей, но не задаёт границы пользовательской команды и не заменяет изоляцию подписок |

«Локальный HTML-стейт» в рекомендуемом варианте означает локальный React state поля, а не состояние всего CustomNode с тяжёлыми дочерними элементами. `onChange` синхронно обновляет отображаемый черновик; задерживать ввод debounce нельзя. Перенос state в отдельный компонент поля соответствует рекомендации React по сокращению перерисовок при вводе. [React: input](https://react.dev/reference/react-dom/components/input#optimizing-re-rendering-on-every-keystroke).

Нормальный commit выполняется по blur / Enter. **Дополнительная обязательная граница — подготовка сохраняемого снимка:** актуальный черновик переносится в документ перед ручным/автоматическим сохранением, AI-оценкой и «Сохранить и перейти». Это уточнение к правилу «только blur / Enter» предотвращает сохранение старого текста, пока поле остаётся в фокусе.

## Границы состояния и перерисовок

1. `TextEditor` внутри CustomNode хранит `draftValue` в локальном `useState`; актуальное значение также доступно через ref для чтения координатором в том же цикле событий. Один ref зеркалирует этот черновик, не создавая независимого источника данных. Аналогичный путь используется для внешних подписей, notes, меток связей, ER-полей и текстовых панелей.
2. Обычный `onChange` не вызывает `setNodes`, `setEdges`, изменение CanvasDocument, полную сериализацию, canonical export, AI-вызов, перерасчёт layout или добавление команды в историю графа. Размер поля во время ввода ограничен его текущим контейнером; ввод не запускает auto-layout всего холста.
3. Компоненты CustomNode/CustomEdge мемоизированы; nodeTypes/edgeTypes и передаваемые обработчики/конфигурация имеют стабильные ссылки. Компонент поля не подписан на весь массив узлов, связей или всё хранилище. Адаптер сохраняет ссылки неизменившихся элементов при commit одного поля.
4. UI сохранения подписан на свои технические признаки отдельно от графа. Первое изменение черновика может переключить `isDirty` и обновить этот индикатор; дальнейшие символы не инициируют обновление общего графа через dirty-state.
5. Переход label из локального draft в CanvasDocument — адресная команда `text.commit` по objectId/fieldPath. Повторный blur после Enter, flush или commit того же значения — no-op без новой записи истории. Если размер блока действительно изменился при commit, обновляются необходимые размеры/handles затронутого узла.

В CanvasDocument хранится только зафиксированный текст. Пока поле редактируется, его черновик является актуальным пользовательским вводом и обязательно учитывается при проверке dirty-state, сохранении и предупреждении о закрытии. Черновики, refs и их обработчики не передаются в API и не входят в семантическую схему.

Если изменяется текст, относящийся к области показанной оценки, UI отмечает «Есть незафиксированные изменения текста». Прежний результат не объявляется соответствующим текущему вводу; точное сравнение semanticContentHash выполняется после commit, не на каждую клавишу.

## Ввод и завершение редактирования

Роль: пользователь. Результат: текст вводится без задержек и фиксируется одной понятной командой.

| Шаг / событие | Поведение | Негативный сценарий |
|---|---|---|
| Начать ввод | Инициализировать черновик из текущего значения; сохранить фокус и позицию курсора | Повторный render, drag другого объекта или ответ save не сбрасывает draft значением из props |
| Печатать, вставлять текст, удалять символы | Изменяется локальное поле; dirty становится видимым с первой правки | Delete/Backspace внутри поля не удаляет узел; выделение текста не двигает холст |
| Enter в однострочном названии | Валидировать и выполнить text.commit | Enter во время IME composition не завершает ввод и не коммитит промежуточную строку |
| Enter в многострочном описании | Вставить перевод строки; commit по Ctrl+Enter / Cmd+Enter и по выходу из поля | Текст не обрезается по первой строке; сочетание для commit также учитывает composition |
| onBlur | Валидировать и применить изменённое значение | Невалидный текст остаётся доступным для исправления, не заменяется старым значением молча |
| Escape вне composition | Предложено отменить часть черновика после последнего commit и показать зафиксированное значение | Последний commit мог быть выполнен автосохранением; Escape не откатывает серверную запись. Для отмены зафиксированного изменения используется Undo |

Внутренний текст блока — многострочное поле, поэтому подчиняется второй строке таблицы: Enter в нём делает перенос, а фиксирует Ctrl+Enter или выход из поля. Уточнение внесено после проверки MVP: автор описывает компонент несколькими строками, и однострочное поле обрезало описание на первой мысли. Однострочными остаются короткие значения — имя поля ER, тип поля, подпись связи.

IME обрабатывается через compositionstart/compositionend и признак composing в keyboard events: Enter выбора символа не считается командой завершения. Если сохранение затронуло незавершённую composition, один intent ожидает её окончания, затем читает окончательное значение и продолжает; фокус не перехватывается. Автотики не создают дополнительные intents во время такого ожидания. [MDN: KeyboardEvent.isComposing](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/isComposing).

Поля используют `nodrag` и при необходимости `nopan`; прокручиваемые textarea — `nowheel`. Горячие клавиши графа учитывают фокус в редактируемом элементе. Ctrl+S / Cmd+S по-прежнему вызывает сохранение редактора, включая активное поле. [React Flow: Utility Classes](https://reactflow.dev/learn/customization/utility-classes).

## Совместимость с двумя режимами сохранения

Координатор из [11-canvas-saving.md](11-canvas-saving.md) получает небольшой реестр активных/неподтверждённых полей, ключ — ID открытия холста + objectId + fieldPath. В нём достаточно refs и операций чтения/валидации/commit. Это локальная часть редактора; отдельное хранилище событий, сервис или библиотека синхронизации не требуются.

1. Каждая правка, включая локальный или невалидный draft, увеличивает `localGeneration` в изменяемом ref координатора. Это O(1) техническое действие, не обновление Zustand/React Flow на каждый символ. Подписчики UI уведомляются только при изменении их признаков, например `isDirty: false → true`.
2. Перед снимком координатор выполняет `flushPendingInputs`: читает актуальные refs, проверяет существование объектов и валидность всех черновиков, затем одним пакетным commit применяет изменённые поля. Перенос уже учтённого draft не увеличивает generation повторно.
3. Проверка и применение выполняются последовательно без сетевого ожидания между ними. При ошибке ни один draft из этого пакета не применяется частично; save/оценка не продолжается с устаревшим текстом. Пользователь видит проблемное поле, dirty остаётся true.
4. После flush фиксируется неизменяемый снимок с `snapshotGeneration`. Редактирование продолжается; ввод после снимка повышает localGeneration, оставаясь локальным до следующего commit/flush. Ответ PUT подтверждает только snapshotGeneration, поэтому такой ввод не объявляется сохранённым.
5. Flush не вызывает DOM blur, не меняет фокус, курсор, выделение или текущую composition. При чистом поле действий нет. Ручной спиннер включает подготовку снимка; автоматический flush использует тихий индикатор и прежний минутный таймер.

Пример: на сервере название `API`, пользователь без blur вводит `API Gateway` → dirty=true, граф пока содержит `API` → Ctrl+S или минутный тик выполняет flush и отправляет `API Gateway`. Во время PUT пользователь дописывает ` v2` → ответ подтверждает `API Gateway`, поле показывает `API Gateway v2`, dirty остаётся true.

## Undo, замена данных и жизненный цикл

- Пока фокус в поле, Ctrl+Z / Cmd+Z относится к текстовому вводу; shortcut графа не выполняется одновременно. При фокусе на холсте Undo/Redo применяется к истории команд документа.
- Обычное редактирование до blur / Enter — одна команда графа. Последовательные flush одного активного поля можно объединять с последней командой той же edit-session, если после неё не было других команд или Undo/Redo. Через чужую команду объединять нельзя; autosave не создаёт отдельной команды «Сохранить» в истории. Это уточняет правило целой пользовательской операции без истории на каждую клавишу.
- Повторная передача прежнего committed value в props не затирает активный draft. При явной загрузке/отбрасывании черновики сбрасываются только после проверки перехода из 11; draft другого canvasId/открытия никогда не применяется к текущему.
- До unmount поля его draft должен быть зафиксирован, явно отброшен действием пользователя или сохранён в том же локальном реестре до разрешения ошибки. Нельзя рассчитывать только на onBlur при удалении компонента. Оптимизация невидимых узлов не должна молча удалять активное поле с черновиком.
- Удаление объекта явной командой убирает и связанные pending drafts; сохранение не воскрешает удалённый объект через запоздалый flush. Для валидного текста перед удалением фиксируется commit, чтобы Undo удаления восстановил последнее значение. Невалидный draft не теряется без явного решения об отбрасывании.

## Приёмка без новой аналитики

На стандартной сцене проверяются быстрый ввод/вставка, фокус, cursor/selection, Enter/blur, многострочный текст, IME, Undo и ввод во время auto PUT. Ожидание пользователя до blur не входит в техническую latency: измеряются отдельно input → видимый символ и commit → отображённое изменение графа; цель <100 ms в локальных прогонах по [09-technical-sli.md](09-technical-sli.md).

React Profiler проверяет границу перерисовок, browser Performance trace — задержку видимого ввода. Обычные клавиши без commit не должны обновлять CanvasDocument или перерисовывать несвязанные узлы/связи вследствие ввода. Единичное обновление индикатора dirty учитывается отдельно. Это будущие проверки реализации, а не утверждение о достигнутой производительности. Кликстрим и новый telemetry collector не добавляются.

## Экспорт и удаление

По 18D подготовка любого экспорта использует flushPendingInputs перед локальным snapshot так же, как save/evaluation, без принудительной потери фокуса. Незавершённая IME-композиция сначала завершается; старый draft не экспортируется молча. Экспорт не меняет серверный saved-generation. По 19A удаление на другом устройстве сохраняет локальный draft для экспорта/явного discard; правила — в [11-canvas-saving.md](11-canvas-saving.md).
