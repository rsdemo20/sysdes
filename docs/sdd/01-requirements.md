# sysdes — требования и сценарии

Статус: Baseline 1.0. Продуктовые решения и технические параметры MVP приняты ответами 1–26; проверяемые цели производительности ещё не измерены. Альтернативы и Deferred-развитие не входят в принятую реализацию.

## Цель и границы

Помогать архитекторам, системным аналитикам и backend-разработчикам готовить разделы System Design: проектировать HLD, логическую модель данных и взаимодействия, фиксировать требования и получать объяснимую AI-оценку решений.

MVP: личные холсты, один текущий холст на весь аккаунт с синхронизацией между устройствами, несколько схем разных типов в одной рабочей области, шаблоны доменов, сохранение/загрузка, общая оценка решения и три отдельные диагностики HLD/ER/Sequence.

Вне MVP предложены: совместное редактирование, команды и публичный шаринг, полный UML/BPMN, генерация приложения/DDL из схем, загрузка произвольных файлов, рисование от руки, импорт Draw.io/Miro, автоматическое изменение решения моделью, мобильный редактор. Экспорт PNG/SVG/JSON и безвозвратное удаление своих холстов с подтверждением входят в MVP по 18D/19A; экспорт Mermaid добавлен по D-43. Импорт Draw.io/Miro остаётся вне MVP: Mermaid отдаётся только на выгрузку. Внутренняя сериализация для сохранения и AI обязательна независимо от пользовательского экспорта.

Импорт собственных шаблонов из внешних форматов и произвольное создание шаблонов пользователями отложены до следующих итераций. По D-45 в MVP входит одна форма пользовательского пополнения каталога: публикация собственного решения действием «Добавить в каталог» после достижения 100%. Такая публикация доступна для чтения и фильтрации как шаблонное решение, но не становится оцениваемым заданием, пока владелец не утвердит рубрику по D-17. Стартовое наполнение по-прежнему добавляется владельцем через миграции; модель и GUI выбора допускают три и более записей в домене. Форматы будущего пользовательского импорта пока не определены.

## Роли и словарь

| Термин / роль | Значение |
|---|---|
| Посетитель | Может зарегистрироваться и войти |
| Пользователь | Владеет своими холстами, редактирует их, запускает оценки |
| Владелец приложения | Настраивает секреты, доступные модели, лимиты и шаблоны через конфигурацию/миграции; GUI администратора не входит в MVP |
| Сессия аутентификации | Подтверждает вход пользователя; не является холстом |
| Редактор | Имеет один активный холст; переключение не создаёт новую auth-сессию |
| Холст / Solution | Сохраняемый документ: контекст задачи, диаграммы, текст и расположение |
| Диаграмма | Именованный экземпляр HLD, ER или Sequence внутри холста |
| Оценка / Evaluation | Запуск по неизменяемому снимку всего решения либо по выбранным диаграммам одного типа |
| Шаблон | Версионируемый комплект HLD, ER и Sequence с общими требованиями и критериями; Q-03 закрыт |

Q-13 закрыт: четыре команды оценки и рубрики, утверждённые владельцем до публикации. Общая балльная оценка и диагностики 1–5 описаны в [контракте результата v2](contracts/evaluation-result-v2.schema.json); формат v1 оставлен только как исторический пример.

| FR-29 | До 1000 сохранённых холстов на аккаунт, максимум один сохранённый AI-отчёт на каждый; без TTL. Удаление холста освобождает место, лимит конфигурируемый, без подписок/тарифов | Уточнение ответа 17 |
| FR-30 | Каталог хранит схематичные шаблонные решения по доменам: состав HLD, логический ER, ключевые взаимодействия, важнейшие метрики и минимальные критерии приёмки. Полная детализация реальных продуктов и длинные наборы метрик в MVP не готовятся | D-38 |
| FR-31 | Карточка задания и шаблонное решение — одна запись каталога с разной мерой раскрытия. | FR-32 | Сложность записи каталога — от одной до пяти звёзд: три звезды задаёт уровень раскрытия (3 — открыто только базовое описание, 2 — плюс состав блоков, 1 — плюс частичная схема), до двух звёзд добавляет резерв собственной сложности задания | D-41 |
| FR-33 | Каталог фильтруется по домену, сложности и происхождению: только стартовые записи, все пользовательские публикации либо маска по тэгу экспорта | D-42 |
| FR-34 | Экспорт схем холста в Mermaid: отдельный документ на каждую присутствующую диаграмму, копирование в буфер обмена и файлы `.mmd`, плюс общий `.md` для документации. PlantUML и Structurizr DSL — последующие итерации | D-43, D-44 |
| FR-35 | Действие «Добавить в каталог» публикует решение пользователя только при 100% по неустаревшей общей оценке. Публикация попадает в каталог как шаблонное решение для чтения и фильтрации и получает тэг экспорта: по умолчанию логин, иначе собственное уникальное значение. Заданием с баллами публикация становится только после утверждения рубрики владельцем | D-45, D-46, D-17 |

Уточнение границ: в MVP техническая отзывчивость проверяется локальными профилями и простыми замерами по 09. Кликстрим, Product/UX analytics, telemetry collector/API/хранение относятся к следующей итерации по 10 и не добавляют функциональных требований к первой версии.

## Языки интерфейса и контента

Поддерживаются ru/en. Язык UI сохраняется как предпочтение браузера; первоначально выбирается поддерживаемый язык браузера, иначе русский. При создании из шаблона его стартовые подписи, условие и критерии копируются на выбранном языке. Опубликованная версия включает оба варианта; доменные/объектные ID, связи и веса рубрики не зависят от перевода. Изменение опубликованного контента требует новой версии.

Язык и вид холста — личные настройки читателя, а не холста: они собраны в панели аккаунта (за кнопкой с логином в углу шапки, вместе со сменой пароля и выходом), хранятся в этом браузере и переживают перезагрузку. Выбранный однажды язык не выбирается заново при каждом визите. Вид холста — толщина контура блоков и толщина связей, по четыре ступени у каждой; каждая ступень одновременно утолщает линию и делает её темнее, потому что толстая, но бледная линия остаётся бледной. Эти настройки не входят в CanvasDocument, не устанавливают isDirty и не видны оценке.

Переключение UI не переводит и не переписывает содержимое уже созданного холста, не устанавливает isDirty и не меняет semanticContentHash. Пользователь может писать на любом языке. Для нового запуска reportLocale выбирается пользователем, по умолчанию равен языку UI; сохранённый отчёт остаётся на языке своего запуска. Переключатель UI, подписи controls и сообщения ошибок доступны на обоих языках; машинные коды API остаются стабильными.

## Текущий холст аккаунта

Сервер хранит один currentSolutionId на аккаунт, отдельно от сессии входа и документа. До создания/выбора первого холста значение null. Выбор другого холста действует на весь аккаунт. Сохранение любого своего документа не меняет этот выбор. Открытые вкладки одного текущего холста используют существующий контроль ревизий; совместное редактирование и автоматический merge не добавляются.

Локальный переход использует «Сохранить и перейти / Отбросить / Остаться». При смене выбора с другого устройства чистый редактор загружает новый холст, а редактор с локальными правками сохраняет их как ожидающий разрешения черновик и предлагает сохранить либо явно отбросить. Старый черновик не становится вторым текущим холстом. Детали и ошибки — в [11-canvas-saving.md](11-canvas-saving.md).

## Сценарии

### UC-01. Регистрация и вход

Роль: посетитель. Результат: учётная запись и действующая auth-сессия.

| Шаг | Действие и результат | Негативный сценарий |
|---|---|---|
| 1 | Ввести логин и пароль; клиент показывает правила | Неверный формат — подсказка у поля, запрос не требуется |
| 2 | Сервер нормализует логин, проверяет данные, хеширует пароль | Неполный/слишком большой JSON — 422/413; частые попытки — 429 |
| 3 | Создать пользователя под уникальным ограничением БД | Одновременная регистрация одного логина — одна успешная, вторая 409 |
| 4 | При входе проверить пароль и создать новую сессию | Неверный логин или пароль — одинаковое сообщение 401; без различения наличия аккаунта |
| 5 | Открыть выбор холста / создание первого | Сеть недоступна — повтор действия; введённый пароль не журналируется |

При выходе сервер отзывает текущую сессию. Q-10 закрыт ответом 15A: забытый пароль сбрасывает оператор через служебную команду после проверки владельца вне приложения; одного логина недостаточно. Старые сессии отзываются, выданный временный пароль необходимо сменить до доступа к редактору/AI. Сценарий и ошибки — в [05-api-and-storage.md](05-api-and-storage.md).

### UC-02. Создание из шаблона

Роль: пользователь. Предусловие: выполнен вход.

| Шаг | Действие и результат | Негативный сценарий |
|---|---|---|
| 1 | Нажать «Новый», выбрать обязательный домен | Домен не выбран — создание недоступно; Custom считается выбранным доменом |
| 2 | Выбрать шаблон; для Custom разрешён пустой документ | Шаблон снят с публикации/чужого домена — 422, предложить актуальный список |
| 3 | Создать копию шаблона с новыми objectIds, сохранить provenance | Повтор HTTP с тем же ключом возвращает тот же холст; ошибка БД не оставляет частичный документ |
| 4 | Сервер выдаёт имя и revision; редактор загружает холст | Конкурентное создание не повторяет номер; потеря ответа обрабатывается идемпотентным повтором |
| 5 | Переименовать при необходимости | Пустое имя/превышение лимита — поле не сохраняется; прежнее имя остаётся |

Предложение: смена шаблона после создания означает создание нового холста. Вставка нескольких заготовок в существующий холст — отдельное расширение, не молчаливая перезапись.

### UC-03. Редактирование смешанного холста

Роль: пользователь. Предусловие: загружен принадлежащий ему холст.

| Шаг | Действие и результат | Негативный сценарий |
|---|---|---|
| 1 | Выбрать/создать именованную диаграмму, добавить блок | Тип блока несовместим с диаграммой — операция отклонена с подсказкой |
| 2 | Заполнить внутренний текст, добавить внешние подписи: onChange меняет локальный draft, blur / Enter фиксирует значение; многострочный Enter сохраняет перевод строки | Четвёртое внешнее поле не создаётся; невалидный draft не теряется, IME Enter не завершает редактирование; детали в 12 |
| 3 | Соединить блоки и задать смысл связи | Несуществующая/несовместимая цель запрещена; связь ER/Sequence не превращается в HLD-стрелку |
| 4 | Добавить требования и бизнес-критерии приёмки, указать область действия и способ проверки | Числовой порог без единицы требует уточнения; критерий-сценарий не требует искусственного числового значения |
| 5 | Переместить/растянуть объекты; undo/redo применяет целую пользовательскую операцию | Перемещение не меняет смысл Sequence; удаление блока показывает связанные сообщения/связи, удаляемые той же операцией |
| 6 | Продолжить работу после локальной ошибки | Неуспешная операция не портит предыдущую модель; некорректный ввод остаётся в поле для исправления |

Input Isolation и исключение для снимков описаны в [12-input-isolation.md](12-input-isolation.md): Save / Ctrl+S / Cmd+S, автосохранение и оценка учитывают активный текст без необходимости убирать фокус. Сохранение не может отправить прежнее значение только потому, что ещё не произошло onBlur.

### UC-04. Сохранение и загрузка

Роль: пользователь. Результат: подтверждённый сервером revision.

| Шаг | Действие и результат | Негативный сценарий |
|---|---|---|
| 1 | Кнопка «Сохранить» / Ctrl+S / Cmd+S показывает «Сохранение...»; общий координатор отправляет снимок всего документа с ожидаемой версией, не блокируя редактор | Нет изменений — без PUT показать «Все изменения сохранены»; сеть/401 — сохранить локальные правки и показать ошибку |
| 2 | Сервер проверяет владельца и модель, атомарно меняет документ | Чужой холст — 404; устаревший revision — 412 без перезаписи; невалидный документ — 422 |
| 3 | Подтверждение обновляет revision и время; isDirty сбрасывается только при отсутствии новых правок после снимка | При потере ответа сначала сверить сервер; новые правки не заменять отправленным снимком и не объявлять сохранёнными |
| 4 | Раз в 60 секунд при isDirty координатор запускает автосохранение с тихим статусом; каждый успешный save начинает новый минутный отсчёт | Без изменений — без запроса; занятый координатор не создаёт параллельную запись; ошибки не сбрасывают isDirty |
| 5 | Выбрать другой холст, нажать «Загрузить» | При dirty-состоянии доступны «Сохранить и перейти», «Отбросить», «Остаться»; сбой или новые правки во время перехода оставляют текущий холст |
| 6 | После подготовки загрузки условно обновить общий выбор аккаунта; заменить открытый документ после успеха | Ошибка загрузки/переключения сохраняет старый документ; конкурентная смена выбора требует перечитать актуальный, без last-write-wins; поздний ответ не меняет другой холст |

Ручное и автоматическое сохранение входят в MVP; Q-05 закрыт. Нормативные правила снимков, минутного таймера, индикаторов, повторов и перехода — в [11-canvas-saving.md](11-canvas-saving.md). Перезагрузка/закрытие при dirty-state или незавершённой записи предупреждает о потере данных средствами браузера, где поддерживается. Восстановление из IndexedDB остаётся вне MVP.

### UC-05. Оценка

Роль: пользователь. Предусловие: открыт холст; для отдельной диагностики есть диаграмма выбранного типа, для общей оценки — содержимое решения в схемах или тексте.

| Шаг | Действие и результат | Негативный сценарий |
|---|---|---|
| 1 | Выбрать «Оценить решение» для всего холста либо «Оценить HLD / ER / Sequence» и диаграммы соответствующего типа | Пустой выбор отдельной диагностики или полностью пустое решение — без запроса; смешанные типы рассматриваются общей оценкой |
| 2 | Через координатор зафиксировать актуальный снимок, сохранить при необходимости и создать оценку по подтверждённому revision; до принятия POST не запускать следующую собственную запись | Конфликт/ошибка сохранения останавливает оценку; редактирование доступно, новые правки не включаются в уже зафиксированный снимок |
| 3 | Сервер проверяет snapshot, модель и лимиты, создаёт job | Невалидные ссылки/переполнение — 422/413; занятая квота — 429; недоступная модель — 503 |
| 4 | UI показывает статус, остаётся доступным редактирование | Повтор кнопки с тем же ключом не создаёт второй job; разрыв вкладки не отменяет принятый job |
| 5 | Сервер сохраняет валидированный результат или явную ошибку | Неверный JSON/выдуманные objectRefs — ошибка результата; таймаут не выдаётся за оценку 1 |
| 6 | Нижняя панель показывает результат, модель, время и версию | После изменения семантики — «Оценка предыдущей версии»; замечания не подменяют данные холста |

При недостатке требований возможен корректный ответ `insufficient_data` с вопросами и частичными замечаниями; числовая оценка может отсутствовать.

## Данные для AI и ограничение хранения

По 16A для оценки разрешены учебные и обезличенные примеры; секреты, персональные данные и конфиденциальные рабочие схемы передавать нельзя. Перед первым вызовом UI сообщает об отправке схем, требований и свободного текста через OpenRouter внешнему провайдеру. Автоматическая очистка/классификация чувствительных данных не входит в MVP.

Q-11 закрыт уточнением ответа 17: на аккаунт до 1000 сохранённых холстов и не более одного сохранённого отчёта на каждый, если оценка сформирована. Холсты и отчёты не удаляются по возрасту. Лимит задаётся серверной конфигурацией (начальное значение 1000), подписки и тарифы не нужны. Auth-сессии, опубликованные шаблоны и финансовые записи в этот счётчик не входят.

Создание обычного холста и конфликтующей копии занимает одно место. Обновление существующего холста и замена его отчёта места не занимают. При лимите создание отклоняется с canvas_limit_exceeded; UI показывает used/limit и предлагает удалить ненужный холст из списка. Автоматического удаления старых холстов/отчётов нет. Отказ создания копии сохраняет локальный черновик с возможностью экспорта. Успешное удаление освобождает место сразу в основной БД.

Сохранённый отчёт включает результат и его исходный снимок для проверки ссылок/актуальности; отчёт может отсутствовать. Четыре команды оценки сохраняются. По 23A последний успешно проверенный результат любой команды заменяет отчёт целиком вместе со снимком. Диагностика может заменить общий отчёт. Новый сбой или invalid_result не удаляет предыдущий; успешный insufficient_data заменяет его с явным статусом. Истории нескольких отчётов нет.

### UC-06. Экспорт холста

Роль: владелец открытого холста или сохранённого локального черновика восстановления.

| Шаг | Действие | Негативный сценарий |
|---|---|---|
| 1 | Выбрать JSON, PNG, SVG или Mermaid | Во время незавершённой композиции текста подготовка ожидает её завершения; невалидный draft отмечается, экспорт не теряет его |
| 2 | Выполнить flushPendingInputs и снять неизменяемый локальный snapshot | Сохранение на сервер для экспорта не требуется; новые правки после snapshot остаются в редакторе и не подменяют содержимое файла |
| 3 | Создать файл и скачать его | Ошибка рендеринга/памяти сообщает о неудаче, не выдаёт пустой или обрезанный экспорт за успешный; документ и dirty-state не теряются |

Mermaid отдаётся отдельным документом на каждую присутствующую диаграмму: HLD как `flowchart`, ER как `erDiagram`, Sequence как `sequenceDiagram`. Один общий `.mmd` не формируется: Mermaid не допускает нескольких диаграмм разных типов в одном определении, и такой файл не вставился бы в Draw.io и Miro. Основной путь — копирование выбранной диаграммы в буфер обмена, дополнительно доступны файлы `.mmd` на диаграмму и общий `.md` с тремя блоками для документации. Mermaid — текстовое представление схемы, а не формат сохранения: layout, provenance и скрытые метаданные в нём не передаются, обратный импорт не поддерживается. PlantUML и Structurizr DSL добавляются в последующих итерациях тем же механизмом.

JSON содержит версию формата, имя, домен, provenance и полный CanvasDocument с semantic/layout; это не внутренний state React Flow. PNG/SVG содержат визуальное представление всего холста, включая внешние подписи и свободный текст, независимо от текущего zoom/pan. Панели редактора, выделение/handles и нижняя панель AI-отчёта в изображение не входят. Секреты, auth-сессии и финансовые данные не экспортируются. Экспорт не отмечает холст сохранённым на сервере. Импорт документов/шаблонов этим действием не добавляется.

### UC-08. Просмотр каталога и выбор карточки задания

Роль: авторизованный пользователь перед созданием холста.

| Шаг | Действие | Негативный сценарий |
|---|---|---|
| 1 | Открыть каталог; увидеть записи с доменом, звёздами сложности, ключевыми метриками и минимальными критериями приёмки | Пустой результат фильтра сообщается явно и не выдаётся за отсутствие каталога |
| 2 | Применить фильтры по домену, сложности и происхождению: только стартовые записи, все пользовательские публикации либо маска по тэгу экспорта | Неизвестный домен или сложность вне 1–5 — 422; маска тэга не раскрывает существование скрытых записей |
| 3 | Выбрать уровень раскрытия карточки в пределах, разрешённых записью | Запись без частичной схемы HLD не предлагает третий уровень; попытка запросить недоступный уровень — 422 |
| 4 | Создать холст из карточки; в документ копируется только раскрытая часть | Скрытая часть шаблона не попадает ни в документ, ни в ответ API; смена уровня после создания означает новый холст |

Звёзды пересчитываются от выбранного уровня раскрытия и резерва сложности записи и показываются до создания холста. Публикация пользователя без утверждённой владельцем рубрики доступна для чтения и фильтрации, но не предлагается как оцениваемое задание и помечается в списке.

### UC-09. Публикация решения в каталог

Роль: владелец холста с достигнутой оценкой 100%.

| Шаг | Действие | Негативный сценарий |
|---|---|---|
| 1 | Открыть «Добавить в каталог» | Действие недоступно без неустаревшего общего отчёта с maximumReached; отчёт диагностики и оценка ниже 100% не открывают действие |
| 2 | Подтвердить тэг экспорта: по умолчанию логин, иначе собственное значение | Занятый тэг отклоняется до публикации; тэг не редактируется задним числом у уже опубликованной записи |
| 3 | Сервер повторно проверяет владение, актуальность отчёта и совпадение документа со снимком оценки | Правка холста после оценки делает отчёт устаревшим и отклоняет публикацию; клиентское значение процента не принимается |
| 4 | Запись появляется в каталоге как шаблонное решение с происхождением «Пользователь» и тэгом экспорта | Публикация неизменяема: изменение холста не меняет опубликованную запись, для нового содержимого создаётся новая версия |

Публикация не делает решение оцениваемым заданием: рубрика утверждается владельцем по D-17. Публикация не переносит имя холста, историю запусков, свободный текст с персональными данными по решению пользователя и не даёт другим пользователям доступ к исходному холсту.

### UC-07. Удаление холста

Роль: владелец холста в списке своих решений.

| Шаг | Действие | Негативный сценарий |
|---|---|---|
| 1 | Выбрать удаление; увидеть имя холста и предупреждение об удалении связанных отчётов без корзины | Отмена не изменяет данные; для открытого dirty-холста требуется явное подтверждение удаления вместе с локальными правками |
| 2 | Подтвердить; сервер проверяет владение, revision и отсутствие queued/running job | Чужой/отсутствующий ID — 404, изменённая revision — 412 с повторным просмотром, активный job — 409; данные остаются |
| 3 | Сервер удаляет документ, отчёты и их входные снимки из основной БД | Ошибка транзакции не оставляет частичное удаление; незакрытый денежный резерв и минимальный учёт стоимости сохраняются без текстов решения |
| 4 | Список обновляется; общий выбор становится null только при удалении выбранного холста | Другая вкладка с локальными правками получает экран восстановления и может скачать JSON либо явно отбросить черновик; автоматическое повторное создание удалённого холста запрещено |

Удаление из основной БД не означает немедленное стирание резервных копий или данных у внешних провайдеров. Эксплуатационные правила для них определяются отдельно до развёртывания; UI не обещает такого удаления. Подтверждение в одной вкладке не разрешает молча отбросить dirty-черновик другой вкладки.
